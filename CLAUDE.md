# Mustang Splits: guide for Claude Code

Cross country pace board PWA for Coach Rankin (Little Chute Mustangs). Used live at practice on an iPhone, often with weak or no signal. Up to 30 named stopwatches; each can follow a workout plan (sections with distance, target, check-in marks, repeats, rest) and shows expected vs actual position.

This file holds only what every session needs: the stack, the permanent rules, the rollback and test process, a map of the code, and an index of the reference files in `docs/`. **Before changing an area, read its file from the index at the end.** Version-by-version history is in REQUESTS.md. The single-file version of this guide (before 2026-10-29) is kept at `docs/archive/CLAUDE-before-split.md`, with a map of where each part went in `docs/archive/split-map.md`.

## Stack and deploy
- Plain HTML, CSS and JavaScript. No framework, no build step, no npm. Keep it that way unless the coach asks.
- Team sync uses the Firebase modular SDK loaded as ES modules straight from gstatic (pinned version, see `sync.js` imports and `SDK_VERSION` in `sw.js`; change both together). Firebase project: `mustang-splits` (separate from Believe Board).
- Hosting: Vercel, connected to the GitHub repo. Pushing to `main` deploys automatically. Do not use the Vercel CLI.
- The coach verifies changes on his iPhone after the deploy finishes. For bigger features, work on a branch and push it: Vercel builds a preview URL he can test before merging.
- Anonymous sign-in only works on Firebase **Authorized domains** (Firebase console > Authentication > Settings). Wildcards aren't allowed, so a branch preview needs its stable branch domain added there (`<project>-git-<branch>-<scope>.vercel.app`).
- Rescue if a deploy breaks the app: `git revert HEAD --no-edit && git push`

## Files
- `index.html`: page shell, nav bar (3.0), bottom tab bar, the four views (Stopwatches, Training (id `workouts`), Team, Data (called Results before 2.10; its id is still `results`)), plus the Race Mode screen (`#v-race`, not a tab).
- `styles.css`: design tokens on `:root` (light and dark), components, phone rules. School colors: Carolina blue `#4b9cd3`, navy `#13294b`, sky `#bfe3f7`.
- `icons.js`: the Lucide icons (3.13, ISC License), loaded before `app.js` as `window.MSIcons` (+ `MSIconsCredit`); built by `tests/tools/make-icons.js`. In `SHELL`.
- `app.js`: all logic in one IIFE. Sections are marked with `/* ---------- name ---------- */` comments. Works fully without `sync.js`.
- `sync.js`: team sync (ES module, loaded after `app.js`). Firebase Auth + Firestore. Talks to `app.js` only through `window.MSApp` (defined in app.js's "team sync bridge" section) and the API object it hands to `MSApp.syncReady()`.
- `firestore.rules`: the Firestore security rules. Not deployed by Vercel; the coach pastes them into the Firebase console.
- `sw.js`: service worker. Network-first for the app's own files with a 3 s timeout, then cache. Fonts and the pinned Firebase SDK cache-first. Firestore/Auth traffic is never cached.
- `manifest.webmanifest`, `icons/`: install metadata and icons.
- `version.json`: the version the running app compares itself against; a newer one installs by itself (auto-update, 2.9).
- `vercel.json`: cache headers for `sw.js` and `version.json`.
- `docs/`: the reference files (index at the end of this file); `docs/design-3.0.md` is the 3.0 design spec, `docs/training-rules.md` the Start workout rules (checked by e2e45).
- `REQUESTS.md`: every request from 2.4.0 on with its status, and the history of each version.
- `tests/`: every test suite (see Testing).

## Rules for every change
1. Bump the version in BOTH `app.js` (`APP_VERSION`) and `version.json`. They must match. Patch for fixes (1.0.1), minor for features (1.1.0). This is what makes the Update banner appear on the phone.
2. Never rename the localStorage key `mustang-splits:v1`. It holds the coach's rosters, workouts and running clocks; renaming it wipes them. If the saved data shape changes, migrate old data inside `migrate()` instead (`load()` and Restore both run saved data through it).
3. If you change caching logic in `sw.js`, bump `CACHE` (for example `mustang-splits-shell-v2`). If you add a new file the app needs offline, add it to `SHELL`.
4. Read the timing engine before touching it (see below). Do a read-only review of `ACT.split`, the rest handling in `tick()`, and `updateLive()` first, and explain the plan before editing.
5. Phone rules: tap targets at least 44 px, inputs and selects at least 16 px font (smaller makes iOS zoom), respect safe areas (`env(safe-area-inset-*)`). Since 3.17 a stopwatch row's labeled action button is the only thing that records a time; Stop is in the row's sheet (a tap on the rest of the row) or a swipe left, one tap there with an Undo in the row; the Stopwatches screen has no tap guards and no two-tap confirmations (see Stopwatch rows with one action button (3.17)).
6. Keep `MAX = 30` stopwatches unless asked.
7. **Data safety (permanent, since 2.6). Every change must keep these:**
   - **No hard deletes.** Removing anything (runner, workout, course, meet, PR, race, mark, history entry, race on this phone, stopwatch with times, checkpoint with times) puts a copy in the trash (`trashPut()`) and, in a team, soft-deletes the Firestore doc (`deleted`, `deletedAt`, `deletedBy`; content kept). Recently deleted restores it (`trashRestore()` → `restoreKind()`). firestore.rules refuse client deletes; the only exception is an admin's "Delete permanently" (purge) for one runner.
   - **Append-only corrections.** A recorded time is never overwritten: `markChange()` appends a version to `m.hist`; saved results get versions in `h.edits` (applied by `modelOf()`). Restore = a new version equal to an old one.
   - **Undo toast instead of confirm** for anything recoverable (`removedSnack()`, at least 6 s, 44 px). Confirms only for bulk/account actions (Clear all times, Clear finished, Stop all, Restore backup/snapshot, Leave team, Stop being admin, Delete permanently).
   - **Snapshot before bulk actions** (`takeSnapshot(reason)`): bulk clears, team create/join/merge, Leave, backup or snapshot restore, purge (and Start a new season in 2.7). Last 10 kept.
   - **Trash, snapshots and the race archive never go in the `mustang-splits:v1` entry** (they live in IndexedDB), and **a save never fails silently** (`saveNow()`: retry lean, then `mustang-splits:race-rescue`, plus the red banner).
   - **A refused Firestore write is never retried in a loop**: `refused()` in sync.js checks membership first; only an invalid membership rejoins.
8. **Pushing on a meet day is allowed** (since 2.8.1, at the coach's request; it used to be forbidden). Never push with a failing suite. `tests/meetday.sh` still reports whether today is a meet day, for information.
9. **Publishing rules:** when firestore.rules change in a way older phones can't follow (2.6 did), push, wait until Settings > Team says every phone is on the new version, then publish. (2.7 was the other case: its rules only add optional fields and collections, so they were published first, then the phones updated.)
   The first line of `firestore.rules` is `// Mustang Splits rules X.Y.Z`: set it to the app version in every push that changes the rules, so the Firebase console shows which rules are published.
10. **REQUESTS.md** lists every request from 2.4.0 on with its status (Live with version and where, Built but not pushed, Planned, Missed). Update it in the same commit as every push, checking the code, not memory.
11. **Rollback-safe data (since 2.13).** Never make a data change an older version can't read. Add fields; never remove, rename or repurpose one. If a change is unavoidable, keep the old fields alongside the new ones, filled in. Before each phase, push a `before-X.Y.Z` tag of the live version (see How to roll back).
12. **No fetching from results sites** (athletic.net, MileSplit and the like): results come in only through the coach's history file (Import). This rule is about results sites, not about the public weather API: race weather comes from Open-Meteo (3.2, see Race weather), which is allowed.

## More permanent rules
The key rules that live in the reference files, mostly in their own words (the full text and its context stay there).
- **Real data never goes in the repo** (the repo is public): no backups, history files or screenshots with real names. Tests use fake names. (The first name + last initial rule is gone: runners have full names.) *(docs/import.md, Data organization (2.11.1))* History files hold minors' full names: `*.history.json` and `data/` are git-ignored, and the repo is public. *(docs/import.md)*
- **Passwords and hashes** *(docs/sync-and-rules.md)*: The salt is fixed app-wide on purpose: the password alone must find the team. Never change `SALT` or `ITERATIONS`; every team would become unreachable. Never change `ADMIN_SALT`. `normName()` is unchanged (it feeds `nameHash()`; changing it would break remembered matches). *(docs/import.md)*
- **Timing:** A stopwatch's time is `Date.now() - startAt` while running, or `pausedT` while stopped. Never count with intervals; the phone can sleep and timers drift. In Race Mode, times are timestamps, never counted. Nothing on the timing path waits for the network: start, split, stop and rest never wait, and nothing is written per tick. *(docs/timing-engine.md, docs/race-mode.md, docs/sync-and-rules.md)*
- **Never reloads during timing:** `timingNow()` = a running stopwatch or a live race (since 3.11 also `raceHold()`: a race in setup or running on this phone, or the race screen open) holds auto-update, a team minimum version, Update, Restore backup and Restore snapshot. *(docs/architecture.md, docs/race-mode.md)*
- **Local first.** `S` in localStorage stays the source the UI renders from. Firestore is a mirror with an offline queue (`persistentLocalCache`). If `sync.js` or the SDK can't load, `SYNC` stays null and the app is exactly the local app. *(docs/sync-and-rules.md)*
- **Records stay raw:** Raw times stay the record everywhere: PRs, season bests, results, Copy/CSV never use ratings; only the Adjusted views, trends, season averages and the team view's Adjusted mode do. *(docs/data-and-charts.md, Race-day difficulty (3.1))*
- **What is shared stays positive:** shared highlights are celebrations only (never a next step, target, check-in or health reason); comebacks share as "strong return to racing" (never a health reason); context-tag notes are limited to 60 characters with the hint "No medical details". The Next step is coaches only, never shared. *(docs/data-and-charts.md)*
- **Templates:** `WK_TPL` ids: never remove or reuse an id (saved workouts carry `tpl`). *(docs/training-and-paces.md)*
- **Credits:** Open-Meteo data is CC BY 4.0, so every place weather appears shows `WX_ATTR` ("Weather data by Open-Meteo.com", linked). The Lucide icons are ISC; the license is in `icons.js`'s header and in Settings > About (`#iconCredit`). *(docs/weather.md, docs/ui.md)*
- **Wording:** "runner" on screen (data still says athletes). CSV column headings did not change, so existing spreadsheets still line up. *(docs/stopwatches.md, Simple first-run UI (2.3))*
- **Code gotchas:** `modal()` reuses `#modal`: attach listeners to elements inside the new HTML, never to `#modal` itself, or they pile up across openings. Never put a `//` comment in the middle of a one-line function. Two functions were once both named `autoName` and the later one silently replaced the other (2.13), so check a name is free before adding a function. *(docs/roster.md, docs/data-and-charts.md, docs/stopwatches.md)*

### Apple HIG and phone UI
Since 3.0 the app follows Apple's Human Interface Guidelines (spec, audit and the feature inventory: `docs/design-3.0.md`; details in docs/ui.md). Rule 5 above holds the phone rules. Also:
- **Type:** `--font-ui` (the system font) everywhere; `--font-clock` (Barlow Condensed) only for clock digits (`.big`, race clock, live bar). All font sizes are rem; `html{font:-apple-system-body}` makes 1rem follow the phone's text size.
- **No zoom when typing (3.7):** a rule at the end of styles.css keeps every input, select and textarea at `max(16px, 1rem)` (iOS zooms below 16 px; 1rem can be 14 px at a small text size). Pinch zoom stays (no maximum-scale; swipe rows use `pan-y pinch-zoom`). `tests/e2e35.js` fails if any field renders under 16 px.
- **Sheets** are bottom sheets (`modal(html,onMount,kind)`); `confirmBox()` is an action sheet; `actionSheet(title, items)` for menus. **Undo bar and toasts** stay above the tab bar (Race Mode keeps its top bar).
- **No emoji on any screen** (`tests/e2e42.js`): icons from `icons.js` (`ic()`), always next to words; badges are icon + word, never the icon alone.
- **No silent buttons:** a button that's off says why (its text, `data-why`/`title`, or a line next to it); rows that can't be edited are not buttons. `tests/e2e30.js` taps every visible button on 16 screens.
- **Contrast:** text ≥ 4.5:1, fills, rings and edges ≥ 3:1, light and dark (`tests/e2e19.js`, `tests/e2e29.js`). Never the colour alone: Girls circle ●, Boys square ■.
- Portrait only. Headless Chrome can't reproduce safe areas or the iOS keyboard; check these on the phone.

## The timing engine in brief
`ACT.split`, the rest handling in `tick()` and `updateLive()` are the delicate part (rule 4). A running, paused or finished stopwatch runs on its own plan copy (`w.plan`, read only through `planOf()`), progress lives in `w.run`, the engine reads time through `nowMs()`, and shared stopwatches are rebuilt from their taps by `replayWatch()`. Read docs/timing-engine.md, then docs/stopwatches.md, before changing any of it.

## How to roll back
Before every phase a tag of the live version is pushed: `before-2.13.0` (= 2.12.0), `before-2.14.0` (= 2.13.0), `before-3.0.0` (= 2.14.0), … `before-3.5.0` (= 3.4.0), `before-3.6.0` (= 3.5.0), `before-3.6.1` (= 3.6.0), `before-3.7.0` (= 3.6.1), `before-3.8.0` (= 3.7.0), `before-3.9.0` (= 3.8.0), `before-3.10.0` (= 3.9.0), `before-3.11.0` (= 3.10.0), `before-3.12.0` (= 3.11.0), `before-3.13.0` (= 3.12.0), `before-3.14.0` (= 3.13.0), `before-3.15.0` (= 3.14.0), `before-3.16.0` (= 3.15.0), `before-3.17.0` (= 3.16.0), `before-3.18.0` (= 3.17.0). `git tag -l 'before-*'` lists them.

To return the live app to a tag (from the repo folder on the Mac):
1. `git checkout main && git pull`
2. `git restore --source=before-2.14.0 --staged --worktree -- .` (any tag; it also removes files the tag doesn't have)
3. **Give the old code a NEW, higher version number.** Phones only install a version newer than theirs (`verLt(APP_VERSION, version.json)`), so set `APP_VERSION` in app.js and `version.json` to one patch above the version that's live now (live 2.14.0 → `2.14.1`). Leave the version.json/APP_VERSION pair matching.
4. `tests/run.sh` (the old suites match the old code), then `git commit -am "Roll back to before-2.14.0 as 2.14.1" && git push`. Vercel deploys in about a minute; phones install it the next time nothing is timing (auto-update, 2.9).
5. Rules: leave the published Firestore rules alone. Every rules version only adds what's allowed, so older app versions keep working under newer rules.
6. If a team minimum version (Settings > Team, `minVersion`) is above the rolled-back number, an admin turns it off or sets it to the new number first.
To undo the rollback: the same steps with the newer tag or commit, again with a higher version number.

**Saved data stays readable both ways.** The localStorage key never changes, and no version removes or renames a field it saved before: new fields are added beside the old ones, and older versions ignore fields they don't know (their `migrate()` keeps the rest). Rule 11 below makes this permanent. Specifics:
- 2.13 shows Varsity/JV races as one Girls or Boys list without changing saved races; the stored division codes (`GV`/`BV`/`GJV`/`BJV`/`OPEN`) and the imported division text stay, so 2.12 still shows its Varsity/JV views. Race Mode saves Girls as `GV`, Boys as `BV`, Both as `OPEN` (the codes 2.12 and the rules know).
- A workout part with an effort and a distance but no time works as effort-based in 2.13; 2.12 shows it as "needs a distance and target time" (nothing is lost).
- 2.14 workout plans and 3.0 settings are new fields next to the old ones (see those sections).
- 3.2 adds `S.places`, `S.weather`, `S.settings.wx`/`raceGeo` and two Firestore collections (`places`, `weather`); older versions ignore them, and their rules (published before 3.2) refuse them quietly (sync.js `quietKinds`).
- 3.18 adds `S.awards`, `S.settings.hlMode` and the Firestore collection `awards` the same way (see docs/season-and-awards.md).

## Testing
All tests live in `tests/` (since 2.6.1) and nowhere else. One-time `tests/setup.sh` (npm packages; a Java runtime in `tests/.jdk` if the Mac has none). **Run every suite: `tests/run.sh`** (about 2 hours since 3.7 on a MacBook, e2e27 and e2e28 alone about 17 min each; one suite: `tests/run.sh e2e8.js`). It serves the repo on :8765, starts the emulators with the repo's current `firestore.rules`, clears them between suites, and ends with "ALL SUITES PASSED" or the failures (logs in `tests/out/`). Push only when every suite passes (meet days are fine since 2.8.1). Suites are listed in `tests/README.md`; new tests go there too. `tests/retired/` holds superseded scripts that aren't run.
More in docs/testing.md (every suite's test notes, emulators by hand).
